# 版本记录：v1.22.5-footer-horizontal-compact-layout

## 1. 本轮目标

本轮目标是修复首页底部 Footer 在桌面端过高、过散、右侧导航中文词组被逐字拆开的视觉问题。用户截图中“柚木知识”“查看推荐厂商”“空间阅读参考”等链接因为所在列过窄，被拆成单字纵排，影响阅读和页面完成度。

本轮属于视觉布局修复和可读性优化。改动集中在首页 Footer 结构、Footer 样式和发布检查，不修改顶部导航结构、柚木好物栏目、推荐厂商筛选、咨询区文案、文章正文、表单脚本或 sitemap URL。

## 2. 背景与上下文

本轮承接 V1.22.4 的全站 Header 缝隙修复。当前工作区已有 V1.22.4 的未提交样式和检查脚本改动，本轮在其基础上继续增量处理 Footer，不回退上一轮改动。

首页 `index.html` 的 Footer 原本由品牌区、用户说明、三组纵向链接和二维码组成。CSS 中 `.footer-inner` 使用 3 列 grid，`.footer-link-groups` 又使用 3 列 grid。这个结构在宽度不足时会让每个链接列非常窄，中文没有空格，浏览器会按单字断行。

## 3. 问题分析

表面问题是 Footer 右侧链接逐字断行，实际原因是链接被放入三组窄列，并且没有对链接文本设置 `white-space: nowrap` 和 `word-break: keep-all`。

另一个问题是二维码被放在第三列之后，但整体 grid 只有三列，导致二维码位置像悬空补位，不像稳定的第四个区域。用户希望 Footer 和顶部导航最大宽度一致，桌面端一行协调展示，移动端再上下排列。

## 4. 候选方案比较

方案一：只给旧链接加 `white-space: nowrap`。

优点是改动最小。缺点是旧三组纵排结构仍然占用高度，且列宽不足时容易横向溢出，不能解决“桌面端一行四区”的目标，因此放弃。

方案二：完全重写 Footer，新增多个复杂模块。

优点是可控性强。缺点是会扩大结构改动，也可能影响数据源或后续生成逻辑。本轮只需要解决布局问题，不需要新增系统，因此放弃。

方案三：轻微调整首页 Footer HTML，把三组纵排链接改为单组横向链接；CSS 将 Footer 明确分成品牌、说明、导航、二维码四区。

优点是符合用户要求，改动范围可控，链接文本可通过 CSS 保持完整。最终采用该方案。

## 5. 最终决策

本轮采用首页 Footer 结构微调加 CSS 覆盖：

1. 保留品牌口号、用户说明、底部导航和二维码四个区域。
2. 将三组纵排链接改为一组横向链接。
3. 只保留用户指定的六个底部导航：柚木知识、柚木好物、查看推荐厂商、社群交流、空间阅读参考、企业合作。
4. 桌面端 `.footer-inner` 使用四列 grid，最大宽度继续与顶部导航一致。
5. `.footer-link-groups` 使用 flex 横排，可自动换行；每个链接设置不拆词。
6. 移动端在 900px 以下改为单列上下排列。

## 6. 具体实现

修改 `index.html`：

- 将 Footer 中原来的三个 `.footer-link-group` 删除。
- `.footer-link-groups` 直接包含六个底部链接。
- 保留 `.footer-qr`、公众号二维码和“关注公众号”。

修改 `styles.css`：

- 新增 V1.22.5 Footer 横向紧凑布局覆盖块。
- `.footer-inner` 改为四区横向 grid。
- `.footer-link-groups` 改为横向 flex wrap。
- `.footer-link-groups a` 设置 `white-space: nowrap`、`word-break: keep-all`、`overflow-wrap: normal`。
- 缩小 Footer 内边距、字号和二维码尺寸，让页面更紧凑。
- 移动端保留上下排列，二维码居中。

修改 `custom/check-release-readiness.mjs`：

- 检查首页 Footer 必须包含六个指定链接。
- 检查首页 Footer 不再使用 `footer-link-group` 分组纵排结构。
- 检查样式中存在 V1.22.5 修复标记。
- 检查 Footer 导航使用横向 flex wrap。
- 检查链接具备不拆词规则。
- 检查 Footer 桌面端四区布局和二维码对齐规则。

## 7. 本轮优点

桌面端 Footer 从“高而散的多列堆叠”变为四区一行展示，整体更接近行业网站底部信息条。

右侧导航改为横向链接，既可自动换行，又不会把中文词组拆成单字。

二维码和“关注公众号”被限制在最右区域内居中显示，不再像悬空内容。

## 8. 本轮缺点与代价

本轮删除了 Footer 中“认识柚喜”“延伸阅读”“先问清楚”三个旧链接，仅保留用户明确要求的六个链接。这个取舍让 Footer 更紧凑，但减少了少量入口冗余。

桌面端四区一行在很窄的窗口下会逐步压缩，因此 900px 以下切换为上下排列。这个断点是为了避免在小屏设备上强行一行导致拥挤。

本轮只处理首页主 Footer。大量内容页使用的是简化版 `content-site-footer`，不含公众号二维码，不属于本次截图问题范围。

- `index.html` 首页 Footer 已保留品牌、说明、横向导航、二维码四个区域。

浏览器插件曾拒绝访问本地 `127.0.0.1:4179` 预览地址，本轮没有绕过该限制使用其他浏览器自动化。最终视觉仍建议在本地或部署后刷新首页 Footer 做一次人工目视确认。

## 10. 本轮结论

Footer 的主要问题不是信息内容过多，而是链接被放进过窄的分组列。把链接降为单组横向导航，并用不拆词样式约束，是本轮最小且直接的修复方案。

## 11. 下一轮建议

1. 如果后续希望全站内容页也使用完整 Footer，可单独评估是否把 `content-site-footer` 升级为统一组件。
2. 公网页面部署后重点查看 1366px 和 1920px 桌面宽度，确认 Footer 一行比例是否自然。
3. 如果还觉得右侧链接偏多，可再评估是否把“社群交流”和二维码入口合并表达。
