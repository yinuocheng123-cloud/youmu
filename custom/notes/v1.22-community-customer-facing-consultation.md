# 版本记录：v1.22-community-customer-facing-consultation

## 1. 本轮目标

本轮目标是优化“社群交流 / 添加柚喜顾问”入口，把页面表达从内部运营视角调整为客户咨询入口视角。

用户不是来理解企业微信、社群机制或内部承接方式，而是想知道：买柚木前为什么要扫码、扫码后能先问清楚什么、能否了解材料、选购、空间方案和推荐厂商资料。

## 2. 背景与上下文

本轮承接 `v1.21.1-vendors-tag-simplify-compact-layout.md`。上一轮已经把推荐厂商页收敛成更紧凑的企业资料库，本轮不触碰推荐厂商标签筛选结构，也不修改柚木好物栏目结构。

仓库中没有独立的 `community/index.html` 文件。当前公网截图对应的是首页 `index.html` 的 `#wechat` 区块。因此本轮遵守“不改 sitemap URL 结构”的约束，优化现有首页咨询区，而不是新增一个社区页面。

## 3. 问题分析

修改前的表达包含 `Enterprise WeChat Community`、“添加柚喜顾问，加入企业微信社群”、“不是马上推销”、“不是广告群”、“企业微信入口”等内容。这些文字解释的是内部承接机制，而不是客户当下最关心的问题。

真正需要解决的是用户的第一反应：我为什么扫码、我能问什么、我能不能先了解再选择。因此首屏需要直接回答“买柚木前，有问题先问清楚”。

## 4. 候选方案比较

方案一：新建 `community/index.html`。

优点是可以做独立咨询页；缺点是会新增 URL，并可能影响 sitemap 结构。本轮用户明确禁止修改 sitemap URL 结构，因此放弃。

方案二：只改按钮文案。

优点是改动很小；缺点是首屏仍然像内部社群说明页，不能解决截图里的核心问题，因此放弃。

方案三：优化首页 `#wechat` 区块和内容源。

优点是不新增 URL，直接改善当前公网可见页面；同时能同步 Header 按钮、二维码卡片和咨询场景。最终采用该方案。

## 5. 最终决策

将首屏小字改为 `Teak Consultation`，主标题改为“买柚木前，有问题先问清楚”，副标题聚焦柚木地板、柚木整装、柚木家具、推荐厂商和真实应用场景。

二维码卡片改为“扫码咨询柚木问题”，说明用户可以先说明城市、品类、预算和疑问，再按需求获取资料或交流建议。

## 6. 具体实现

修改 `index.html`：重写 `#wechat` 区块的首屏文案、咨询场景列表、二维码卡片标题、二维码说明和风险边界；同步页脚中的咨询入口表达。

修改 `data/site-content.js`：同步首页内容源中的咨询入口文案、二维码标题、咨询场景和 footer 联系说明，避免后续动态内容回到旧口径。

修改 `script.js`：把动态生成的移动端 CTA 文案从“添加柚喜顾问”改为“咨询柚木问题”。

批量更新公开 HTML 中可点击入口的锚文本，把按钮类“添加柚喜顾问”改成“咨询柚木问题”。这不改变链接结构，只调整用户可见文案。

修改 `styles.css`：新增 V1.22 咨询入口样式，让首屏标题更直接，二维码卡片层级更清楚，咨询场景列表更像客户问题而不是内部功能点。

修改 `custom/check-release-readiness.mjs`：增加 `index.html#wechat` 专项检查，拦截“企业资料入口、广告群、马上推销”等内部表达和认证、担保、最低价等风险词，并要求出现“买柚木前、有问题先问清楚、扫码咨询、柚木地板、柚木整装、推荐厂商”等客户化表达。

## 7. 本轮优点

首屏能直接告诉用户扫码的理由：买柚木前先问清楚。

左侧卖点从内部权益改为客户问题场景：材料真假、地板整装家具怎么选、空间方案、推荐厂商资料、先避坑再沟通。

二维码卡片不再像社群入口说明，而是咨询动作说明。

不新增页面，不改 sitemap，不影响推荐厂商页和柚木好物栏目。

## 8. 本轮缺点与代价

由于仓库没有独立 `community/index.html`，本轮实际优化的是首页 `#wechat` 区块。若未来确实需要独立咨询页，需要另开一轮并同步 sitemap 规则。

本轮将全站按钮文案统一为“咨询柚木问题”，会弱化“顾问”这个角色词，但换来更外部化、更容易被客户理解的动作表达。

## 10. 本轮结论

当前咨询入口应优先回答客户问题，而不是解释社群机制。把入口改成“先了解，再选择”的咨询页口径后，用户更容易理解扫码的价值。

## 11. 下一轮建议

1. 部署后刷新公网首页 `#wechat` 区块，重点看首屏标题、二维码卡片和按钮文案。
2. 如果后续需要独立咨询页，再单独评估是否新增 `community/index.html` 与 sitemap。
3. 可继续收敛页脚里的“社群交流”说法，但不建议在本轮扩大到全站栏目命名调整。
