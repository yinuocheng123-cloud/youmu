# 版本记录：v1.22.4-header-top-gap-anchor-fix

## 1. 本轮目标

本轮目标是修复全站顶部 Header 上方在 hash 锚点直达或滚动时露出页面内容的问题。用户反馈的典型页面是 `about/index.html#teak-culture`，截图中 Header 顶部出现一条能看到正文或背景的缝隙，影响页面精致度。

本轮属于 Bug 修复和视觉稳定性优化，只处理 Header 顶部承接、锚点 offset 与发布检查，不修改柚木好物结构、推荐厂商标签筛选、咨询区文案、文章正文、表单脚本或 sitemap URL。

## 2. 背景与上下文

本轮承接 V1.22.3。前一轮只精简首页 `#wechat` 右侧二维码卡片文案，并确认当前仓库没有独立的 `community/index.html`，咨询入口仍在首页 `index.html#wechat`。本轮与咨询文案无关，问题出现在全站固定 Header 与锚点滚动的视觉关系上。

当前全站页面普遍使用 `.site-header.global-site-header`。Header 本身是 `position: fixed; top: 0`，但它的视觉背景主要由 `.site-header::before` 承担。历史样式里该伪元素使用了 `inset: 8px -14px` 这类写法，意味着深色背景层顶部天然向下缩进，顶部会存在一段透明区域。

## 3. 问题分析

表面现象是：访问带 hash 的页面后，浏览器把目标区块滚到视口上方，Header 虽然固定在顶部，但 Header 真实深色承接层没有覆盖到最顶端，导致页面内容或背景从 Header 上沿露出。

核心矛盾不是某个页面文案或单个锚点位置，而是全站 Header 的圆角浮层视觉与 fixed 定位之间缺少顶部遮罩。`scroll-margin-top` 和 `scroll-padding-top` 虽然已有旧值，但在部分页面、移动端和较高 Header 场景下不够统一，容易出现锚点内容贴近 Header 或从 Header 后方露出的感觉。

主要原因判断：

1. `.site-header::before` 顶部缩进让 Header 上边缘存在透明承接区。
2. 页面内容在 hash 直达后会滚到 Header 背后，透明区就会显示正文或背景。
3. 全站锚点 offset 多次被历史版本覆盖，数值不完全统一。

## 4. 候选方案比较

方案一：把 Header 改成普通不圆角的全宽顶部栏。

优点是最彻底，不会出现浮层边缘漏底。缺点是会破坏当前品牌导航的视觉系统，影响范围大，也不符合本轮“保持 Header 视觉风格”的要求，因此放弃。

方案二：只调大 `scroll-margin-top`。

优点是改动小。缺点是它只能减少锚点目标被遮挡，不能解决 Header 顶部透明区本身会露出背景的问题。如果用户滚动页面，顶部缝隙仍可能出现，因此放弃作为唯一方案。

方案三：保留现有 Header 风格，补顶部遮罩并统一锚点 offset。

优点是局部、稳妥、对导航结构无影响。通过 `body::before` 在 Header 下方、页面内容上方加固定遮罩，阻止内容从最顶端透出；同时让 `.site-header::before` 顶部补到 `top: 0`，并提高全站锚点 offset。最终采用该方案。

## 5. 最终决策

最终采用 CSS 兜底方案：

1. 在 `styles.css` 新增 V1.22.4 覆盖块。
2. 将全站 `scroll-padding-top` 和 `[id]` 相关 `scroll-margin-top` 提升到更贴合 Header 高度的数值。
3. 增加 `body::before` 固定顶部遮罩，桌面端使用深咖色承接 Header，移动端使用浅色承接移动端 Header。
4. 将 `.site-header` 层级统一提升到 `z-index: 1000`，避免被遮罩盖住。
5. 将 `.site-header::before` 的顶部覆盖补到 `top: 0`，消除伪元素自身的顶部透明区。

## 6. 具体实现

修改 `styles.css`：

- 新增 V1.22.4 样式块。
- 设置 `html { scroll-padding-top: 128px; }`。
- 设置 `[id]`、`.knowledge-topic-card`、`.solution-card`、`.good-section`、`.good-things-stream-section` 的 `scroll-margin-top: 128px`。
- 桌面端增加 `body::before` 固定顶部遮罩，层级为 999，低于 Header，高于页面内容。
- Header 层级统一为 1000，Header 背景伪元素补 `top: 0`。
- 移动端将锚点 offset 提高到 136px / 140px，并把顶部遮罩改为浅色，匹配移动端 Header。

修改 `custom/check-release-readiness.mjs`：

- 读取 `about/index.html` 和 `styles.css`。
- 检查 `#teak-culture` 锚点必须存在。
- 检查 `styles.css` 必须包含 V1.22.4 修复标记。
- 检查存在足够的 `scroll-padding-top` 与 `scroll-margin-top`。
- 检查存在固定顶部遮罩、`.site-header` 顶部贴合和足够层级、`.site-header::before { top: 0; }`。

## 7. 本轮优点

本方案不改 HTML 结构，不改导航项，不改文章内容，影响面集中在全站样式兜底。

Header 顶部不再依赖页面背景自然露出，hash 直达和普通滚动都由固定遮罩拦住内容透出。

锚点 offset 更统一，`about/index.html#teak-culture` 和 `solutions/index.html#good-cultural` 这类直达链接更不容易被 Header 遮挡。

## 8. 本轮缺点与代价

`body::before` 是全站兜底遮罩，会在所有页面顶部常驻一条很薄的承接层。这是为了阻止内容透出而接受的视觉代价。

锚点 offset 提高后，跳转目标与 Header 之间的距离会比旧版略大，尤其移动端可能显得更保守。但相比锚点被遮挡或顶部露缝，这个代价更可接受。

本轮没有重构历史上多处重复的 Header 和 scroll offset 样式，只在尾部做覆盖，因为本轮目标是修复明确视觉 Bug，不扩大到全站样式清理。

## 10. 本轮结论

本轮判断：顶部白缝不是单页内容问题，而是 Header 浮层背景承接与锚点滚动叠加后的全站视觉问题。用顶部遮罩加锚点 offset 的组合，比单独调锚点距离更稳。

## 11. 下一轮建议
