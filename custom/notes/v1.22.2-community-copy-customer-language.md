# 版本记录：v1.22.2-community-copy-customer-language

## 1. 本轮目标

本轮目标是继续优化当前“社群交流 / 咨询入口”的客户化表达，让页面从“咨询柚木问题”的功能描述，进一步变成用户真实会接受的第一眼话术：看柚木，不急着买，先把材料、空间、预算和厂商问清楚，再决定是否深入了解。

本轮属于页面文案和首屏比例优化，不修改柚木好物结构、推荐厂商标签筛选结构、好物文章正文、厂商详情正文、表单脚本或 sitemap URL 结构。

## 2. 背景与上下文

本轮承接 `v1.22-community-customer-facing-consultation.md`。上一轮已经确认仓库没有独立的 `community/index.html` 文件，公网截图对应首页 `index.html#wechat` 区块。因此本轮继续优化首页现有咨询区，不新增页面，不改 URL。

V1.22 已经把内部社群说明改成客户咨询入口，但文案仍偏“平台解释服务逻辑”，右侧二维码卡片也仍像运营入口说明。用户本轮要求把左右两侧都改得更自然，重点表达“先问清楚再决定”。

## 3. 问题分析

左侧旧标题“买柚木前，有问题先问清楚”虽然方向正确，但语气仍偏口号；旧描述里“扫码咨询”出现得比较直接，读起来像平台在推动用户咨询。

右侧旧标题“扫码咨询柚木问题”偏功能按钮式表达，二维码卡片没有形成“先问一个问题”的低压力动作。

视觉上，上一轮标题和二维码卡片已经可用，但本轮希望首屏比例更舒服：标题不过分压迫，二维码不抢主信息，Header 与锚点区域之间留出安全距离。

## 4. 候选方案比较

方案一：新增独立 `community/index.html`。

优点是可以做完整咨询页；缺点是会新增 URL，并触碰本轮禁止修改 sitemap URL 结构的约束，因此继续放弃。

方案二：只替换标题，不改二维码卡片和按钮。

优点是改动小；缺点是左右表达仍不统一，Header 按钮仍过长，因此放弃。

方案三：同步优化首页 `#wechat` 文案、二维码卡片、Header 按钮和比例样式。

优点是直接作用于当前公网可见区域，且不会影响好物和厂商页面结构。最终采用该方案。

## 5. 最终决策

左侧主标题改为“看柚木，先问清楚再决定”，描述改为围绕柚木地板、柚木整装、柚木家具和户外应用的材料、做法、预算、厂商判断。

五个咨询点改为更轻的客户问题场景，不再使用“我想……”句式，也不写成服务承诺。

右侧二维码标题改为“扫码，先问一个柚木问题”，降低动作压力；底部边界改为“仅提供柚木知识、选购沟通和企业资料参考，不作交易担保”。

Header 右侧按钮和移动端 CTA 统一改为“先问清楚”，比“咨询柚木问题”更短、更克制。

## 6. 具体实现

修改 `index.html`：更新 `#wechat` 区块标题、说明、五个咨询点、二维码标题、二维码补充说明和底部边界；首页主按钮和页脚沟通入口同步为“先问清楚”。

修改 `data/site-content.js`：同步首页内容源中的 hero action、知识 lead magnet、wechat 标题、说明、benefits 和二维码卡片文案。

修改 `script.js`：动态生成的移动端 CTA 文案改为“先问清楚”。

批量更新公开 HTML 中 `nav-cta` 和 `mobile-menu-cta` 的锚文本，把 Header 与移动菜单按钮从“咨询柚木问题”改为“先问清楚”。该批量更新只触及导航按钮文本，不改文章正文和好物正文。

修改 `styles.css`：新增 V1.22.2 样式覆盖，缩短 Header CTA 尺寸，给 `#wechat` 设置 `scroll-margin-top`，调整左右列比例、标题字号、二维码卡片宽度和二维码尺寸。

修改 `custom/check-release-readiness.mjs`：把咨询区必备文案更新为“看柚木、先问清楚再决定、扫码，先问一个柚木问题、不作交易担保”等；同时对“不作交易担保”做负向边界例外，允许这句风险说明，但继续拦截其它正向或单独的“交易担保”表达。

## 7. 本轮优点

文案更像客户真实需求：先问材料、空间、预算、厂商，再决定是否继续。

二维码动作更自然，从“扫码咨询”变成“先问一个问题”，降低用户心理门槛。

Header 按钮更短，不再抢主导航。

首屏比例更稳：标题控制在桌面端最大 66px、移动端 36px 到 44px；二维码控制在约 240px 到 266px；二维码卡片最大宽度约 420px。

## 8. 本轮缺点与代价

由于仓库仍没有独立 `community/index.html`，本轮实际优化入口仍是 `index.html#wechat`。如果未来确实要做独立页面，需要新增页面并重新评估 sitemap 约束。

全站 Header CTA 被统一改为“先问清楚”，这会弱化“咨询柚木问题”的直白 SEO 文案，但换来更短、更自然的用户动作。

“不作交易担保”包含“交易担保”子串，检查脚本需要专门做负向例外。这是为满足用户指定边界表达的必要妥协。

## 10. 本轮结论

咨询入口继续从“功能说明”转向“客户决策前的问题场景”。本轮的核心结论是：页面应少强调“咨询”这个平台动作，多强调“先问清楚再决定”这个用户利益。

## 11. 下一轮建议

1. 部署后刷新公网首页 `#wechat`，重点看 Header 锚点跳转后是否留出安全距离。
2. 若后续仍觉得“社群交流”导航文字偏内部，可另开一轮评估是否改成“咨询交流”，但需要同步全站导航一致性。
3. 如果未来新增独立咨询页，再单独处理 `community/index.html` 和 sitemap，不建议在当前任务中混入。
