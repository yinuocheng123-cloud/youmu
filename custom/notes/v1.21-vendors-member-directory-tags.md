# 版本记录：v1.21-vendors-member-directory-tags

## 1. 本轮目标

本轮目标是把“推荐厂商”从导航分类页口径调整为行业网站中的企业资料展示页。用户明确要求不要把推荐厂商做成“柚木地板厂商 / 柚木家具厂商 / 柚木整装厂商”一类下拉层级，也不要新增厂商分类 URL。

本轮属于功能补充与结构口径修正：保留一个全站 Header 入口，在推荐厂商页面内部用主题标签帮助用户理解企业方向，并让企业卡片可以同时拥有多个标签。

## 2. 背景与上下文

上一轮 `v1.20.6-good-things-note-card-more-button.md` 的核心结论是：入口要保持克制，具体内容放回对应页面或栏目内部。这个原则对推荐厂商同样适用。

修改前，`vendors/index.html` 已有 6 家企业资料入口，但页面仍包含“按方向查看”“品牌索引”等容易让用户理解成分类导航的结构。全站 Header 中“推荐厂商”也仍然是下拉菜单，包含推荐厂商首页、公开信息参考库或品牌索引、企业合作等子项，不符合“顶部导航只保留一个推荐厂商入口”的要求。

## 3. 问题分析

表面问题是 Header 和页面正文仍有分类或索引感。核心矛盾是“推荐厂商”不应承担内容分类导航角色，而应承担企业资料展示角色。

如果继续保留下拉分类，后续很容易把企业强行归入单一方向，导致同一家企业同时涉及材料、空间、家具、地板时无法自然表达。更稳妥的做法是保留单入口，在页面内部用轻量标签筛选企业卡片。

## 4. 候选方案比较

方案一：继续保留推荐厂商下拉，并把子项改成更温和的文案。

优点是改动小；缺点是仍然保留了导航分层，会继续让用户误解为分类黄页，因此放弃。

方案二：为每个方向新增厂商分类页。

优点是扩展空间大；缺点是违背“不新增厂商分类 URL”和“不改 sitemap URL 结构”的约束，也会把企业强行单分类，因此放弃。

方案三：Header 只保留推荐厂商单链接，页面内部用标签筛选企业卡片。

优点是入口清楚、结构轻、企业可多标签、不会新增页面，也符合行业资料库口径。最终采用该方案。

## 5. 最终决策

全站 Header 中“推荐厂商”改为单个链接，指向 `vendors/index.html`。

`vendors/index.html` 改为企业资料展示结构：页面顶部说明推荐厂商的资料库定位，主体包含内部主题标签和企业卡片。标签只用于当前页筛选，不生成新 URL，也不作为导航层级。

## 6. 具体实现

修改 `vendors/index.html`：更新 SEO 描述和 hero 说明；删除“按方向查看”“品牌索引”这类页面级分类感模块；新增 `vendor-filter` 标签筛选区；用 6 张 `vendor-card` 展示现有企业资料。

修改 `styles.css`：新增 `vendor-filter`、`vendor-filter-chip`、`vendor-grid`、`vendor-card`、`vendor-tags`、`vendor-tag`、`vendor-meta`、`vendor-status` 等样式，保持行业资料卡的稳重视觉，并补充移动端单列与按钮换行。

修改 `script.js`：新增只作用于 `data-vendor-filter` 和 `.vendor-card[data-tags]` 的轻量筛选逻辑。默认显示全部，点击标签后只显示包含该标签的企业卡片。

批量更新公开 HTML Header：将“推荐厂商”的桌面下拉和移动端 details 统一收口为单个链接。柚木好物下拉、Header 其他结构和 good-cultural 等好物锚点未调整。

修改 `custom/check-release-readiness.mjs`：增加推荐厂商页结构检查、标签检查、企业卡片字段检查、风险表达检查和厂商分类 URL 引用检查。

修改 `custom/check-navigation-consistency.mjs`：增加全站 Header 推荐厂商单入口检查，拦截 `vendors-menu-*` 和移动端推荐厂商 details 回潮。

## 7. 本轮优点

推荐厂商入口更清楚，用户从 Header 只进入一个企业资料页，不再面对额外下拉层级。

企业卡片可以同时拥有多个主题标签，避免把企业粗暴归类到单一方向。

标签筛选不改 URL，不新增页面，不影响 sitemap，也不会干扰柚木好物栏目切换逻辑。

检查脚本能防止推荐厂商下拉、风险背书文案和厂商分类 URL 回潮。

## 8. 本轮缺点与代价

本轮没有删除历史存在的 `vendors/flooring-sample.html`、`vendors/whole-decoration-sample.html`、`vendors/workshop-sample.html` 等旧示例页，因为用户本轮只要求不新增厂商分类 URL，且未要求删除历史页面。当前方案只是不再从 Header 或推荐厂商首页强化这些路径。

部分企业的区域、类型和资料状态仍然较保守，很多字段只能写“资料待补充”。这是为了不编造企业事实，代价是页面信息密度暂时有限。

## 10. 本轮结论

推荐厂商更适合作为企业资料库入口，而不是新的内容分类体系。内部标签筛选能够表达企业多方向属性，同时保持全站导航简洁。

本轮继续继承 V1.20.6 的经验：入口层保持短，具体内容和辅助理解放在页面内部。

## 11. 下一轮建议

1. 后续若企业补充授权资料，可优先完善卡片中的所在区域、企业类型和资料状态。
2. 如果旧示例页不再承担展示价值，可单独开一轮梳理 `vendors/` 历史示例页是否需要保留或转为资料说明页。
3. 标签数量暂时保持克制，新增企业时优先复用现有标签，避免再次演化成分类导航。
